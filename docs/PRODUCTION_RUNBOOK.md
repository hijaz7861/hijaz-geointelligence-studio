# Documentary Production Runbook

This runbook is the minimum path from research to a reviewable release candidate. It does not bypass editorial review or media-rights checks.

## 1. Define the assignment

Record the topic, intended audience, language(s), target runtime, delivery aspect ratio/resolution, deadline, and client acceptance criteria. Do not begin a factual documentary from the synthetic sample fixture.

## 2. Build the source and claim ledger

For every material claim, record:
- stable claim ID and exact claim wording;
- source URL, publisher/author, publication date, access date;
- source type (primary record, official statement, independent reporting, expert analysis, or other);
- what the source supports and any limitations;
- corroboration or disagreement from independent sources.

Label information as verified fact, attributed official claim, independent reporting, analysis, or unverified claim. Do not present an allegation as established fact. For conflict-related topics, avoid operational targeting details and prioritize context, civilian impact, and verifiable public information.

## 3. Script and translations

Create original narration. Attach source IDs to factual sentences. Separate narration from on-screen text and visual directions. Have a qualified human review the script and every translation for meaning, context, and names/dates. Do not use synthetic placeholder text in a deliverable.

## 4. Media and rights

For each image, video, map, music track, voice, and sound effect, record the origin, creator, license/permission, attribution requirements, restrictions, and proof location. A “publicly viewable” URL does not establish reuse rights. “Original” assets still need evidence of authorship/ownership or applicable permission. Exclude unresolved assets.

## 5. Assemble and quality-check

- Export to the agreed format and resolution.
- Verify the video file is readable and has the expected dimensions/duration.
- Check that subtitle timestamps are ordered, valid, and aligned with the final edit.
- Review narration pronunciation, audio peaks, clipping, music levels, cuts, text legibility, factual captions, and visual context.
- Confirm the final render and subtitle file are the exact versions reviewed by the editor.

## 6. Approvals and evidence bundle

Complete the project approval metadata for script, translation, media rights, and final video. Run the validation script, then generate the release evidence bundle according to `docs/release-evidence-bundle.md`. Inspect every blocker; do not suppress blockers merely to obtain a green status.

The bundle is an evidence record, not an approval engine. A generated report does not prove the underlying claims or rights are true, and it never authorizes publication by itself.

## 7. Handoff checklist

- [ ] Client brief and acceptance criteria recorded
- [ ] Final script and sources reviewed
- [ ] Translation reviewed (where applicable)
- [ ] All media rights documented and reviewed
- [ ] Final render and subtitle file checked
- [ ] Validation command completed and output retained
- [ ] Evidence bundle generated and blockers resolved
- [ ] Human final-video approval recorded
- [ ] Client handoff includes output files, source/rights manifest, validation evidence, and known limitations

## Current repository caveat

The checked-in sample project is a synthetic placeholder, not a completed documentary. A real topic, approved script, licensed media, render, subtitles, and completed approvals are needed before a client-facing final production can be declared complete.
